## Highlights

- **A stage can declare that it consumes no sibling stage's output**, via
  `pipeline.ci.independent_stages` (and the CD equivalent). It then depends on
  preflight alone instead of waiting for a stage whose artefacts it never
  reads.
- **The fixed graph is not loosened.** Nothing here can add a dependency,
  invent an edge, or change the order stages render in. The only thing it can
  do is remove an edge the repository does not have.
- **Nothing changes for a repository that does not use it.** Rendering every
  managed file on v1.5.0 and on this release is byte-identical, comments
  included — so unlike v1.5.0, this one needs no fleet sync.

## What was wrong

The stage graph is fixed on purpose: preflight → build → (test, end2end). That
is the right default, and it is what makes a central pipeline central.

But an edge in that graph asserts something concrete — that the later stage
consumes what the earlier one produced — and for some repositories the
assertion is simply false. wardnet's end2end suite rebuilds the daemon from
source inside Docker (`Dockerfile.test`). It reads nothing `build` uploads. Its
hand-rolled `pr.yml` knew this and ran the two concurrently: `tests-e2e` had
`needs: preflight` and nothing else.

Adopting the pipeline as-is would have serialised them:

| | hand-rolled `pr.yml` | gt v1.5.0 |
|---|---|---|
| build stage (slowest leaf, Check Daemon 11m) | parallel with e2e | 11m |
| E2E Daemon | 24m | 24m |
| **PR wall-clock** | **~24m** | **~35m** |

Measured from run 32688637246, not estimated. Eleven minutes added to every
daemon pull request, spent waiting for an edge that does not exist.

That is a bad trade to force on a repository, and a worse precedent: the
pipeline should not cost more than the thing it replaced in order to be
adopted.

## What changed

```yaml
pipeline:
  ci:
    stages: [preflight, build, test, end2end]
    # end2end rebuilds the daemon from source inside Docker and consumes
    # nothing the build stage produces.
    independent_stages: [end2end]
```

which renders:

```yaml
  end2end:
    needs: [attest, preflight]
    if: needs.attest.outputs.validated != 'true' && needs.preflight.outputs.run-end2end != 'false'
```

## What it deliberately cannot do

This is a statement about the repository, not a reordering knob. A named stage
drops its **sibling** dependencies and lands on preflight alone. It cannot add
a dependency, invent an edge, or reorder anything — so
"a central pipeline every repository can rearrange is not a central pipeline"
still holds. Removing an edge you do not have is not rearranging.

Two constraints fall out of that, and both are enforced rather than merely
documented:

- **preflight is never dropped.** It produces no artefact; it is the gate that
  decides whether a stage runs at all, and the rendered `if:` reads its
  outputs. Dropping it from `needs:` would leave a condition that can never be
  true — a stage that silently never runs.
- **`preflight` cannot be declared independent.** It has no sibling dependency
  to drop, so saying so is rejected rather than quietly ignored. Likewise a
  stage that is not enabled, a duplicate, and any declaration made while that
  pipeline is disabled.

## Detaching a stage does not ungate it

Worth stating plainly, because it is the one way this could have gone badly
wrong: a stage named in `independent_stages` is still in `ci-gate`'s `needs:`.
A failing end2end still blocks the merge. Only its start time moves.

A performance change that quietly punched a hole in branch protection would be
the worst possible outcome here, so it is pinned by a test rather than left to
review to notice.

## Upgrading

**Nothing to do.** The field is `omitempty` and default rendering is untouched
— verified by rendering every managed file on v1.5.0 (`bc668c9`) and on this
release and diffing, which leaves them byte-identical including comments.

`gt repo check` stays green across the fleet with no re-render, and gt's own
repository needed none either. This is the opposite of v1.5.0, which left every
orchestrator drifted by a comment change and wanted a `gt repo fleet sync`.

Adopt it per repository, only where the claim is actually true: the stage reads
none of the artefacts the stage it would otherwise wait for produces. If you
are not sure, leave it out — the default edge costs time but never correctness,
and this is the one setting where being wrong means testing a build you did not
wait for.
