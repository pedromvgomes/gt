## Highlights

- **gt is built on go.vipengele.org.** The root command, flags, configuration,
  logging, paths and self-update now come from `go.vipengele.org/cli/core`,
  `config` and `update`. gt's own `internal/ui` and `internal/update` are gone.
- **`gt --version` is now `gt version`** (also `gt version --json`), printing
  `v3.0.0 build <commit>`.
- **Releases are signed.** `checksums.txt` carries a minisign signature,
  `checksums.txt.minisig`, and `gt update` verifies it with a public key
  embedded in the binary.
- **The cancelled background update check is fixed.** A check cut short by the
  command finishing was recorded as done, which suppressed retries for 24
  hours. It is no longer recorded, so the next run checks again.
- **A major version, because it breaks `@v2` and `@v1` callers.** Their
  reusable workflows run `gt --version` against the newest release, which no
  longer has the flag. See the rollout note below.

## Breaking changes

- **`gt --version` is removed.** Use `gt version`. Output is `v3.0.0 build
  <12-character commit>` instead of `3.0.0 (commit …, built …)`; `--json`
  prints the same fields as an object. A binary installed with `go install`
  reports `dev`.
- **`gt help <command>` is removed.** Use `gt <command> --help`.
- **Unknown configuration keys are errors**, in the global config and in
  `.gt.yaml`. Messages take the form `key: problem: "value" from file:line`.
- **`.gt.yaml` may set only `worktree_types`, `ssh`, `setup` and `profiles`.**
  `auto_update`, or any other key, is an error that stops every command run in
  that repository. `worktree_types: []` in `.gt.yaml` is an error. An overlay
  that sets an `ssh` map replaces the global map; one that leaves `ssh` unset
  keeps the global maps. `profiles` and `setup.templates` still merge by name,
  in place.
- **Errors print as `gt: <message>`**, with indented detail rows, instead of
  `ERROR: <message>`. Configuration errors show `file:line` rows.
- **Exit codes.** Usage errors (an unknown flag, the wrong number of
  arguments, a mutually exclusive flag pair) exit 2 with the library's
  wording. Other errors now exit 1 where they exited 2: a bad worktree spec,
  not found, folder exists, unknown profile, an untrusted setup refused
  without a terminal, a sync orphan refusal. A required prompt with no
  terminal (`set-auth`'s user) is a usage error naming `--user` and exits 2.
- **Yes/no prompts are strict.** Anything other than `y`, `yes`, `n`, `no` or
  Enter is an error (exit 1). In particular, a mistyped answer to `gt wt rm
  --branch`'s force-delete question fails after the worktree is already
  removed.
- **End of input at a prompt aborts** with `aborted` (exit 1) instead of
  taking the default. A prompt is still only asked when stdin is a terminal;
  otherwise the default is taken.

## Rollout (fleet CI)

Governed repositories call gt's reusable workflows at a moving major tag. The
callers that pin `@v2` or `@v1` install the newest gt release and run
`gt --version`. Merging this release publishes v3.0.0 immediately, and from
that moment the reusable workflows fail in every such repository until
`gt repo fleet sync` rewrites its callers to `@v3`. The reusable workflows at
`@v3` run `gt version`. The upgrade steps below do both.

## Changed behaviour

**Configuration**

- The config file is no longer created on first run; only `gt config edit`
  creates it, with the defaults and a reduced set of comments.
- The `gt config` group is the library's: `path`, `show`, `validate`, `edit`.
  `gt config show` prints every key's merged value with the layer it came from
  (default, file, `.gt.yaml` overlay, environment), in a table with a header.
- `GT_<KEY>` environment variables override scalar keys, for example
  `GT_WORKTREE_TYPES`, `GT_AUTO_UPDATE_ENABLED` and
  `GT_AUTO_UPDATE_CHECK_INTERVAL`.
- `GT_HOME=<dir>` relocates configuration (`<dir>/config`) and state
  (`<dir>/state`).
- The global config stays at `$XDG_CONFIG_HOME/gt/config.yaml`, or
  `~/.config/gt/config.yaml`, on macOS too. State lives under
  `~/.local/state/gt`.

**Output**

- Info and success messages move from stdout to stderr. Stdout keeps only
  result text: plans, lists, "Next steps" and diffs.
- The `INFO:`, `SUCCESS:`, `WARN:` and `ERROR:` labels become the glyphs
  `ℹ`, `✓`, `⚠` and `✗`. Colour is decided per stream.
- `--quiet` also silences warnings, except the warning for a setup template a
  repository declares for itself, which always shows.
- Prompts go to stderr. A value prompt ends in `[default] ` without a colon;
  yes/no prompts show `[Y/n]` or `[y/N]`; three-way prompts read
  `… y/n/d (d = show …) [y]`.
- New root flags `--log-level` and `--log-format`. `--log-level` together with
  `-v` or `-q` is a usage error.
- Ctrl-C cancels the running command's context.

**Exit status**

- `gt wt nuke`, `gt wt prune-branches` and `gt repo fleet merge-pending` exit 1
  when any item fails, even though each failure is also warned about
  individually; `--quiet` hides the warnings but not the exit status.

**Self-update**

- `gt update` runs the downloaded binary before installing it, verifies the
  minisign signature of `checksums.txt`, and refuses a Homebrew-managed
  binary and a `dev` build.
- `gt update --check` exits 10 when an update is available.
- The background check runs only when stderr is a terminal, and waits for up
  to 250ms after the command (50ms before) for a result.
- A cancelled check is not recorded. A check that fails is recorded and
  throttled until the next `check_interval`.
- The check is unauthenticated: it never sends `GH_TOKEN`.
- Update state moves from `~/.cache/gt/update.json` to the state directory
  (`~/.local/state/gt`). The old file is left in place and can be deleted.

**Releases**

- Releases are signed with minisign. `checksums.txt.minisig` is published next
  to `checksums.txt`. The reusable workflows and `install.sh` still verify the
  SHA-256 only; the signature is checked by `gt update`.

## Kept

- Command aliases: `gt wt` is also `gt worktree`; `rm` is also `remove` and
  `delete`.
- The five mutually exclusive flag pairs, which exit 2 when both are given.
- `-v`, `-q` and `--no-color`, and the `gt completion` command.
- Global config path on macOS, and the `.gt.yaml` per-repo overlay by name
  merge, including the trust gate for templates a repository ships itself.
- The release archive layout and the `main.version` ldflags stamp.

## Upgrading from v2.2.0

```sh
gt update                          # or reinstall with install.sh, or your package manager
gt repo fleet sync --owner <name>  # rewrites reusable workflow refs to @v3
gt config validate                 # unknown keys are now errors
rm -f ~/.cache/gt/update.json      # update state lives under ~/.local/state/gt
```

Replace any `gt --version` in your own scripts with `gt version` (or
`gt version --json`).
